# HISTORY-DESIGN-MEMO

历史区（`src/ui/tui/zone/main/history`）视口机制的设计过程记录。**设计中，未定稿。**

范围：块成品的形状、视线行、重排。别的事不在这里。

---

## 前提

- 用户不改字体。行高恒定，终端**宽度**变了才重排（块内折行重来，块高全变）。
- **行不是一等公民，块才是。** 行序是块序列的副产物；要规范管理的是块。
- 视线友好字段是**行序**上的位置（离终端顶部第几行），不是物理高度。字体一改它就没意义 —— 所以前提是字体不变。

## 现状（改动前）

- 块认得自己的每一行：折好行之后的序列，高度就是它的长度。
- 但行是块的私产：对外只有「这有多少行」和「把这几块的行拼给我」，没有「第几行是什么」。
- 跨块的连续坐标不存在，是渲染时从某一块出发一行一行挪出来的。块不在手上，坐标就断。
- 块的成品今天不带切点信息，`\n` 断的行与宽度硬折的行混在同一条序列里，没有区分。

## 定下的（2026-10-12）

### 一、块要交出每行的切点

块的成品必须知道每一行是**从哪个字符到哪个字符**：`\n` 断出来的行与宽度太窄硬折出来的行都要，两者都落在成品行序列上，都要有切点。

### 二、视线行

- 一枚配置：离终端顶部第几行是人的视线友好行。键名 `config.ui.tui.zone.main.history.focusLine`，默认 3（从终端顶部往下 3 行）。归历史区读。
- 前提是字体不变；宽度变了才重排。

### 三、重排时以视线行为界临时切块

宽度一变、行高没变：

1. 读出视线行当前落在哪一块的哪一行。
2. 记住那一行的切点。
3. 在那个切点处把这一块**临时切成两个块**，两块各自重新排版。
4. 结果是视线附近的内容不因整块重切而整体位移。

例外只有一个：视线行正好落在两块本来的分界处（分无可分），此时不切，行为回落。

切出来的临时块，重排完成后是留着还是合回去 —— **未定**，见下。

### 四、视线行是分割线，不是某一行

视线行指的是行与行之间那条线，像 `b` 与 `c` 之间那一条。所以坐标是「第几条分割线」：一共 `行数 + 1` 条，第 0 条在首行之上，第 n 条在末行之下。

这条坐标在重排时钉在两行之间，切块也从这条线切。

于是「视线行正好落在两块分界上、分无可分」不再是一条例外：分界线本身就是一条分割线，切不动只是因为那里已经是边界。

### 五、常驻圈

历史区**必须管理**的常驻成品缓存，以视线行为中心：

| 组成 | 说明 |
|---|---|
| 视线行所在的那一块 | 分割线正好落在两块之间时没有这一块 |
| 视线行往上 margin 块 | |
| 视线行往下 margin 块 | |
| 任务清单 | 特殊状态，不在块的圈里，另外常驻 |

margin 半径默认 32，做成 config 让用户自己改。这是「必须管理」的下限，不是上限。

在完整成品缓存的前提下，常驻与否不产生渲染性能收益（显示与否不改变「搬上屏」的成本）；它是**取数与窗口策略**，管的是滑动时不出空隙。


### 六、临时块只为继承切点

切分不是为了产生新块，是为了让视线附近那段的**切点**继承下来：宽度变了，视线附近的文本按老切点重排，内容因此不跳。切出来的两块照常渲染，只是带着从变动前传下来的切点。

### 七、32 是预算上限

只留视线行所在块 + 上下各 margin 块 + 任务清单，顶天就记这么多块的成品。超出的块成品一律扔出去，不再多留。

### 八、成品按块管，丢弃只按整块

成品块是管理单位：缓存里一块一块地进、一块一块地出。丢弃只按整块，不存在「只丢这块的一部分行」这种做法。

块的对外能力只有两问：我多高；我的行给我。

### 九、视口就是一个分割线坐标

视口只由一件事决定：视线那条分割线在块序列里的位置，加上终端高度。滚动 = 分割线加一格减一格；resize = 分割线不动、圈里的块按切点重排。

没有「跟随末尾」这个独立状态，也没有锚点之外的第二个位置来源。

### 十、md 正文按段渲染，前向状态全部消除

块内 md 正文渲染的调度单位是**段**：把一个块的内容切成一段一段的区，每段独立渲染，段内自己排。段与段之间只有顺序关系，段外的行判定不依赖段内。

切出来的段：

1. 正文段（无状态的普通行：段落、标题、分隔线）
2. 围栏代码段
3. 表格段
4. 引用段
5. 列表段
6. 行尾硬折的续段

段的分隔线全部可由正则或几个布尔判定：

| 段 | 起点 | 终点 |
|---|---|---|
| 围栏代码 | 行首三个反引号（可带语言标记） | 配对的结束围栏 |
| 表格 | 表头行 + 分隔行 | 不再是表格行 |
| 引用 | 连续的 `>` 前缀 | 前缀断掉 |
| 行尾硬折 | —— | 行尾两空格或反斜杠，只看上一行结尾 |
| 列表 | 自身是列表行（`-`、`*`、`+`、`1.`、`1)`） | 出现一行「既不是列表行、又无缩进」 |

列表区的边界只看两个布尔：**自身是不是列表行**、**自身有没有缩进**（深浅不管）。层级、续段、嵌套全在区内自己算，不出区。

结果：**已支持的 md 语法里没有剩下的前向状态。** 标题、段落、分隔线本来无状态；行内构造（行内代码、粗体、斜体、删除线）是行内流里的样式切换，逐行独立，不参与分隔、不单独成段。

数学、脚注、缩进代码块不在此列：今天它们降级为纯文本，不渲染成块结构。

### 十一、需要方向无关的渲染

- **流式增量**：新来的行只影响自己，老行不动。
- **预热**：程序加载时把用得到的语法预先编译。今天已有：只编转录里真实出现过的语言，从尾部往前排队。
- **工具卡的语法上色不参与段模型**：它的语言在构建卡片时已经挂在行上（读文件按扩展名、bash 固定 shell、JSON 参数固定 json、兜底按工具名），逐行上色、逐行独立，倒序渲染对它无障碍。工具卡不是性能重点，md 才是。

### 十二、渲染分两种：流式与非流式

按内容是否已经完整来分：

- **非流式**（已完工的块，内容全在手上）：走消除前向状态那条路，**先出尾部**是它的正常出口。resume 落在这里。
- **流式**（还在长的块）：走增量，新来的行接上；倒序不适用，末尾一直在变。

### 十三、倒行渲染 = 倒段渲染

段是渲染的最小单位，也是倒序的唯一刻度：

- **段间真倒着来**：先出最后一个段、再往前，凑够一屏就停；排在目标段之后的段根本不排。resume 要省的大头在这里。
- **段内倒着取、正着算**：段内的行序列先正着扫一遍生成，取出时倒着给；段内不再另设倒序机制。

于是「段」一个概念担三件事：前向状态的边界、渲染的调度单位、倒序的刻度。

### 十四、旁白走本地节

- 旁白不进库、不进上下文，只活在内存里；它是会话内的东西，不跨会话。
- 历史区自己维护一条**仅追加**的槽序列：一格一个自然数序号，只增不改，整条序列不动。
- 一格只放一样东西；写进去就不再改，但可以整格丢弃。
- 格子里是块时只记它的块号；格子里是旁白时，旁白的内容由历史区自己存（渲染简单，不算性能负担）。
- 寿命：短命的那条，下一条**常驻**的东西（一条常驻旁白，或任何一个块）插进来时整格丢弃，之后回到那一段也不显示；常驻的那条自己持有内容，不离开这条会话就一直在，随时可以恢复。
- 切会话（resume 界面选了别的对话）→ 本地节整条销毁，按新会话重建。

### 十五、块的身份链

- 上游给两块原料：没落盘的尾巴（无块号）与落盘的批次（带块号）。
- 尾巴挂**内容哈希**（类型 + 正文 + 调用号 + 工具名与参数 + 结果 + 文本算出来的那个）：内容一长它就变，这一块写完才定下来。块号靠这个哈希认领——落盘批次直接带号，回合结构答复给 `{号, 哈希}` 对，前端重算哈希去认。
- 历史区这一侧：没落盘挂哈希，落盘换成块号，位置不动。

### 十六、历史区对上游的期待

1. 一条按时间排好的块序列，每块给身份（落盘 = 块号，没落盘 = 内容哈希）、类型、全部字段、是否还在流。
2. 落盘只把哈希换成块号，块在序列里的位置不动。
3. 认领不撞：内容一样的两块不能互相认领。
4. 视口两端（块号）与是否贴在末尾，换回要不要更老/更新的页；旁白表（文本 + 档位 + 寿命）；任务清单、工作目录、代、会话号。

## 还没定

- 旁白在视图里要不要一个只增的号：session 的旁白表没有号也没有位置，历史区要靠"这条我记过没有"决定开新格还是复用旧格。
- 重排开销分摊：宽度一变，圈里这些块全部重排——一帧做完还是分帧来。
- 块成品是否常备切点表，还是只在重排那一刻现算。
- 段之间的边界要不要留进块成品（重排时直接按段重切，还是每次重新扫边界）。

## 不变式

- 块按时间顺序排布，视口里出现的就是整块；不存在「只要一个块的某一行」这种请求。块的对外能力只有「我多高」与「我的行给我」。
- 一块的哪一行被画，说明那一块在视口里；在视口里的块必然在常驻圈内，成品必然在手上。所以「成品丢了、行序还占着屏」这种状态不存在，不需要为它设计画法。

## 上一版机制（本轮要替换的）

位置记「哪一块的第几行」，不记行号。滚动意图攒着，渲染帧里从锚点一行一行走查凑够视口；窗口滑动按块，块走了行也走。走到块装不下一屏时补空行 —— 这是行坐标缺位留下的补丁。

## 定下的（2026-10-13 / 2026-10-14）

上面那批 10-12 的一个字不动。这一批和上面冲突的，以这一批为准。

### 十七、角色

- **上游 = session（数据中心）**：管原料（块），背后是库。
- **下游 = 历史区**：管成品（渲染好的行）。
- **树**：直接读上游那份结构，不自己管成品。

### 十八、块的身份链（修正十五）

- **哈希归上游，历史区不碰。** session 手里是纯原料，用哈希匹配一下没有代价；历史区手里是成品，身份一变就得重排，重排是用户看得见的，攒起来就是卡。
- 历史区的身份是**本地号**。
- 号这么分：0 是本次对话新的第一条消息那个位置（不问来源，启动时先来一条系统消息也算）；过去全负，从 0 往前数，最新的过去块是 -1，再往前 -2、-3；新的消息从 0 起往上走。号发出去不改、不重发。
- 号在开场就分完：上游一次给全整条结构，负数区一次算清。
- 块号与本地号的对照留着，翻回来还是同一个号。
- 一律先有块号才有正式身份；没有块号的都在可变区，而可变区永远在全场最底下。

### 十九、本地节（补十四）

- **悬空索引允许**：号可以先占着，块号还没来、内容还没取 —— 索引在、东西不在。
- **短命旁白死后，那一格变成「请显示下一块」**：不删、不塌，变成一个指令格。于是渲染不用管哪一格空了没有，照着格子顺序往下排就行；空白被表达成一个格子，而不是一个要算出来的状态。

### 二十、常驻圈与丢弃（补五、七、八）

- 常驻圈、丢弃只按整块这些不变。**裁剪只发生在落户那一刻。**
- **活跃回合期间不裁**：只要还有一个回合在活跃，可变区那片内存就给宽容，不管这次会话多离谱都完整留着 —— 读者随时可能滑到任何地方。
- 落户那一刻怎么裁，看视线在哪儿：
  - 视线就在刚落户的那一段里 → 走常态，按视线上下 32 裁，多的丢掉，再要看就重排。
  - 视线不在这段里（读者在更早的回合里逛）→ 尾部额外宽容：成品同时盯两处，视线上下 32，加可变区底部往上 32（给贴底准备的）。两处挨着时算一处。
- **先时序裁，再顺序裁。** 时序那道丢写入时间最早的（进原料缓存那一刻记的时间，重新取回来会刷新），因为读者已经离开那儿了；顺序那道按视口边缘往外数。时序那道要先跳过读者当下待着的那一段。

### 二十一、上游（session）那一半

- 两个缓存分工：内容缓存装块号到内容，固定 128 块，管的是占用；结构缓存装回合怎么管块，是索引，不装内容。
- **结构一次给全**：恢复一条会话时，把整条结构一次给完（有哪些回合、每个回合管哪些块号、每块的写入时间），之后只走增量。它只是个索引，早给晚给都要给。
- **取数按回合，不按块数。** 一次要多少由 `config.ui.session.askedEachTime` 定，默认 32。
- **一个口，两种报法，没有第三档**：
  - 跳跃中：只报回合号，意思是我正跳到这一回合去。
  - 跳完了：报具体要哪几块，块号点出来。方向不用单报，块号自己说明白。
- **减量**：连着跳起来的时候，回来的量从 32 递减到 8（第 3 次起指数往下，底是 4）。判断减不减的状态由 session 自己维持。
- **回执**：历史区静默 `config.ui.tui.zone.main.history.restYourMouse`（默认 300 毫秒）之后判定「该初始化了」，发一条回执。回执只干一件事：把 session 的减量状态抹掉。它不等答复、不触发补问；补齐由历史区按常态自己再要。
- **内容缓存什么时候丢**：活跃回合期间不动；回合结束、块号全部齐了之后，从最新那一块往前数，第 129 块以及更老的内容全丢，哪怕它们和当前回合同属一个回合（一个回合本来就可能超过 128 块）。
- **开场**：先立一个 32 块的虚拟区；是老会话就先发三个回合。

### 二十二、键位与接口

- 历史区自己声明：Ctrl+T、Ctrl+O、PageUp、PageDown、Ctrl+↑/↓、滚轮（`Claim::Wheel`）。
- Ctrl+Shift+Home / Ctrl+Shift+End：把视线所在这一回合的第一个块、最后一个块分别对齐到视线线。前提是这一回合上下都有别的回合；对正在跑的那个最新回合，End 没有意义。
- Ctrl+PageUp / Ctrl+PageDown：一个走到整条会话的第一条消息（滚到最顶），一个走到最后一条（回到底）。这两个键今天没人占；Ctrl+Home / Ctrl+End 留给编辑器，不抢。
- Shift+滚轮：一格一个回合。事件数不数，**按帧合并** —— 一帧里不管来几个滚轮事件，只走一步（触控板会一次发十几个，惯性尾巴还拖长）。
- `focus(turn, block)`：对外调用，回到这个回合的这一个块，表现是这一块的头落在视线线下面。只对不可变区有效。
- 树那边：Esc 两下进树；树里按 S 只列用户消息；Enter 是后悔药（回退到那一刻），Shift+Enter 是去看看（把选中的节点放到视线线上）。开关 `config.ui.tui.zone.tree.cherishYourWords`，默认 false；打开之后后悔药挪到 Shift+Enter，怕手滑把记录剪了。

### 二十三、渲染机制（设计意图）

- 整条历史是一根很长的竖条。最左边那一列是结构，回合一个接一个排着，块挂在回合下面；这一列是全的、一直在，不随滑动增减。
- 节点右边才是用户看的区域，那块地方不一定真有一份渲染好的东西。「号在」和「成品在」是两码事。
- 成品靠预测做出来。手上的输入就两样：焦点在哪，以及用户刚干了什么（滚了、跳了、还是停下来了）。
- **只维护两样状态**：焦点，以及这一段有没有成品。「这块是不是空的」「在不在视线里」都由焦点算出来，不单独存。
- 目标是让用户觉得正常就够：他看向哪里，那里在他看之前或者当下就已经有了；他不看的地方不做。
- **空白就让它空白。** 不检查空行、不主动拉、不补空行。这一块的用户体验是故意牺牲的 —— 维护「还有没有空行」太烦，不值。

### 二十四、对上游的期待（换十六）

1. 一条按时间排好的块序列，每块给身份（落盘 = 块号，没落盘 = 无号）、类型、全部字段、是否还在流。
2. 落盘只换身份，块在序列里的位置不动。
3. 认领不撞：内容一样的两块不能互相认领。
4. 一个按回合点名的口：今天那几扇门都是「块号 + 块数」的开区间，不认回合号。
5. 全量结构一次给（回合 → 块号区间，带写入时间）。
6. 一个口收历史区的两种报法（跳跃中报回合号、跳完报块号），外加一条不等答复的回执。
7. 旁白的表（文本 + 档位 + 寿命）。
8. 任务清单、工作目录、代、会话号。

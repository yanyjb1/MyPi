# TUI-设想

tui 侧目前想到的形态，**还没定稿**。`session` 内部的形态另有 `SESSION-目标形态.md`；这份只管「session 之外、tui 之内」的那些事。

---

## 一、原则

1. **分而治之、大胆放权。** 前后端原则相反：后端要一个明晰的状态，所以库的读、库的写、切块都集中；前端杂，所以谁的事谁管，**谁最终消费谁解释**。
2. **action 与事件分开。** 用户干的（按键、粘贴、鼠标、提交、打断、回退）是 action，由最终消费它的那个区解释；不是用户干的（后端推送、git 快照、resize、重绘、空拍）是事件。
3. **组件不碰后端。** api 的调用全在 `session`，各区只走它的统一入口。

---

## 二、两层缓存，两个数字

| 层 | 是什么 | 预算 | 归谁 |
|---|---|---|---|
| 原料 | 待渲染的块 | `config.ui.session.preloadCache`（128） | `session` |
| 成品 | 渲染好的卡片行 | `tui.renderMargin`（64） | 历史区 |

## 三、事件与键鼠归属

事件只有两条来源，归一化到一条枚举，APP 收到后**广播**，只给显示区；键鼠是用户行为，按**谁消费归谁**定点下发。

### 事件的两条来源

- **运行时事件**（我们自定义的）：回合开始、回合结束、内容（块到来、工具调用、旁白）、时间（空拍、期限到）、连接（断线、重连）。
- **用户行为不产生事件**：它走 `Action` 那条线（按消费权定点），后果要么在区内部（命令归输入区），要么走 `Request` / `Handover`；状态变了靠每帧读视图，不靠事件。
- **系统环境事件**（我们定义不了的）：尺寸变化、挂起与恢复、焦点得失、终端没了（SIGHUP / SIGTERM）、输出断了（EPIPE）。
- 空拍 = 屏幕上还有东西在动但没有新东西进来，循环自己给自己发一个信号。期限到 = 先前说好「到某个时刻要发生一件事」，现在到了（Esc 双击窗口、重连退避、重试间隔）。
- 回退、压缩、打断是**用户行为**（action），不是事件；它们的后果（回合结束、块到来、占位落地）才是事件。

### 键身份

- 归一化到「一个值能说出 Ctrl+D」的粒度：字符或具名键 + 修饰键（Ctrl / Alt / Shift）
- 不带 crossterm 的 `kind`（Press / Repeat / Release）与 `state`（CapsLock / NumLock / Keypad）—— 那两个字段会让同一个物理键互不相等
- 落不到这个粒度的（没有键盘增强协议时 Ctrl+Shift+字母）归「其他」，没人认领
- 归一化只做投影，不做解释：Ctrl+D 不翻译成「退出」或「删字符」

### 翻译与下发（APP 与大区）

- 键鼠在最上面翻译好：按了哪个键、粘了什么、滚了哪边。主区以下拿到的就是「按了哪个键」，没有别的语义
- 循环只给正在显示的大区两样东西：事件（广播）、键鼠（定点）
- 宽高并进事件，不再走 `attach` / `on_resize` 两条口

### 显示权（大区与大区）

- 同一时刻只有一个显示的大区，APP 手里一张表记着是谁
- 大区自己决定干不干：不干了就指名下一个大区；APP 执行交接，然后通知新的大区干活
- 不指名下一个 = 没人干活 = 循环退出（`/q` 就是主区不干了、不指名）
- 大区之间不直接说话，只有「指名」这一个动作

### 注册表（两级三张）

- APP 级：大区注册表（在册的大区）+ 显示权账本（现在是谁）
- 主区级：子区注册表 + 键位表（键 → 子区）
- 键位表三档行：具体键（Ctrl+D → 输入区）、类别（粘贴 → 输入区、滚轮 → 历史区、任意字符 → 输入区）、兜底（其余丢掉）
- 建法：**形状取「子区自己交表」**（谁消费谁登记），**检查取编译期 match**（同一个键登记两次 = 不可达分支，编译期报），运行期零表；借键那一小份走运行期同一张表

### 借键即转发（子区之间）

- 输入区只判一件事：**我挂起了**（光标在触发词里）。挂起就借键。
- 借多少、借哪几个，由借键者自己声明 —— 输入区不知道也不关心借的是谁、借的是什么。
- 键一旦借出去，输入区不再解释：那一份进运行期键位表，由表直接路由给保留区。
- 键不借出去时，一个键只有一个意思。

### 通知（hook）

- 回合结束且焦点不在（用户不在终端前）→ 发一条通知
- 发通知那一步按平台来，平台由服务端给；一个事件可以挂一条自定义命令

### 命令（不在本域）

- 命令的声明在 `src/commands.rs` —— 跨域共享单位（名字、别名、参数种类、`scope`、帮助文本），域外只读。
- 命令的实现落在**命令所属域**：服务端的归服务端，前端的归各自前端。本域一行都不实现。
- 输入区对命令只做两件事：认出 `/xxx` 是一条命令（`commands::split`），然后按归属递出去 —— 要和 session 打交道的递主区代办，本域能自己落地的落地，其余整句走 `submit`。
- **命令不是事件**，是输入区的内部事务。主循环只捕捉键，连命令存在都不知道。
- 活跃回合只挡用户消息，命令照放。
- 出地界只有两个门：要落到会话的走 `Request`（提交、打断、回退、切会话），要交显示权的走 `Handover`。没有第三个门。子区不直接和外部打交道：子区交 `Request` 给主区，由主区代办；主区才有 APP 的 id。

### 补全的触发与确认（2026-10-12 定）

触发就三类，别处不弹：

1. 斜杠命令：输入框的**第一个字符**是 `/` —— 整行都算命令线，光标在命令名那一段给命令名，落在参数位就按参数的种类给（路径 / 模型 / 档案 / 没有候选）。
2. 绝对路径：空格 + `/` + 系统根目录那一层的首字符（` /e` → `/etc`）。光一个 `/` 意思太多，所以多打一个字符才认。
3. 相对路径：空格 + `./`（` ./src`）、空格 + 工作区里**已有的目录名** + `/`（` src/`）、空格 + `../`（` ../xxx`）、空格 + `~/`（` ~/Doc`）。

- 筛选逻辑只有一份（前缀 + 模糊），三类的差别只是**原料**：命令名来自 `COMMANDS`（`src/commands.rs` 那张表随时会加，补全只读它，不许自己抄一份）、路径来自一级目录扫描、模型与档案名来自视图里那两份名单。
- 确认一个「下面还有东西」的候选（`more` 为真）就**当场把下一层列出来**，不用再敲字符。多敲一个字符只用在绝对路径那一条上 —— 那是意图确认（光一个 `/` 也可能是在写 URL）。
- Tab 归补全借：弹窗开着时 ↑↓ 选，**Enter 或 Tab 都算确认**；没被借走时 Tab 就是制表符，照常写进文本。
- 借不借键看的就是这套触发：输入区自己那条「光标在触发词里」的判定（`refresh_hang`）和这里同一套规矩，别处不借。
- 弹窗开在保留区，行高进场报备、从进场到离场不变。

### 输入区是什么（2026-10-11 定）

- 纯输入器：编辑器（业务不动，含撤销重做与输入历史）、状态行、提交。
- 它不知道有没有面板、有没有弹窗；它只知道「键借出去了」。
- 翻译表不需要上下文：`translate(键) → 动作` 一张纯表。首行、末行、正在翻历史都是编辑器自己的状态。
- Esc 不借出时就是打断（唯一意思）；空闲时那一下的两击窗口开节点树，只在 Esc 没被借走时走。
- 活跃回合 + 输入框有内容 + 连按两下 Enter = 先 Esc 再 Submit，只针对非命令。
- 退出不是键：`/q`、`/quit`。Ctrl+D 只向前删一个字符。
- 行高自限按内容换行数，上限 1/5 终端高；挂起走握手，输入区是唯一知道动态行高的人。
- 状态行七个组件各自过滤全局广播的事件、数据从视图读，不需要状态管理。
- 鼠标不引入：只认滚轮；拖选文本按住 Shift 归终端自己，拖文件不管。

### 保留区（工位）与临时工（2026-10-11 定）

- 保留区是**工位**：一次只坐一个临时工（补全、`/usage` 面板），坐不下第二个。没人坐 = 空闲态，一行空行（工位还在，所以布局不跳）。
- **叫工由输入区决定**：输入区发一个用工信号，指定叫谁。没有例外 —— 路径补全也走这条。
- 闭环：输入区发信号 → 临时工收到 → 临时工向保留区报备（要多高 + 要哪些键）→ 保留区与输入区打交道（确认行高、取键位）→ 键位由输入区转发进来 → 临时工自己解释、自己画。
- 行高：进场时报备一次，**从进场到离场一个字都不变**（不缩也不涨）；退场回空闲态（一行空行），下次进场重新报备。行高抖动毁体验（路径补全早年的教训）。
- 临时工的素养（共用契约）：能收用工信号、能报备行高与键位、自己解释借到的键、自己画自己那几行。
- **能力边界**：临时工是输入器的延伸 —— 输入区能实现的信号它才能实现，输入区不能实现的它也不能。它要对外做任何事，一律由输入区代劳。
- **内部自由**：它自己的交互解释在自己内部（按 Esc 取消补全、不进入补全状态；用量面板开着按 Esc 退出）。
- 汇报链：输入区自己的行高 + 保留区的行高 → 主区（它持有终端高）→ 历史区拿剩下的可用行。
- 临时工不发 `post`、不做本地命令、不 `submit`。

### 显示权与 session（大区与 session）

- 显示权同时是**和 session 交互的权利**：要显示就得拿原料，拿原料就得和 session 说话
- 大区**以 app 的名义**说话：session 侧只有一个 id，所有请求都用它，服务端看不出是哪个大区在用
- 没有大区持显示权 = 主循环退出 = 关连接：ipc 的计数归零，会话侧取消观看并回收活状态
- 登记只是一份状态，不必建表

### 行高（聊天大区的内部约定，未来重构三个子区时）

- 仲裁留在主区（APP 把高度报给主区）—— 「聊天大区与其子区」的内部约定，不挂到通用契约上
- 变动只有两个来源：输入区的内容变了、保留区被激活
- 挂起走一个握手：触发方要回执，输入区拿到回执才正式挂起 —— 于是输入区是唯一知道动态行高的人（它知道自己多高，也知道保留区要占多高）
- 输入区变了 → 通知主区（中间商，手里有最准的全局高度）→ 主区算历史区剩余预算 → 通知历史区

## 四、各区自管（放权）

| 区 | 自己管 |
|---|---|
| 主区（`zone/main`） | 行高仲裁、三个子区的布局 |
| 历史区（`zone/main/history`） | 成品缓存、锚点、钉底、滚动意图、折叠开关、**分组**（一条工具往返 = 一张卡）、**思考态与待办渲染的状态**（自己从读到的块里推）、画 |
| 输入区（`zone/main/input`） | 编辑器、撤销、粘贴、语义、状态栏各组件、**命令的解析与递出** |
| 保留区（`zone/main/reserved`） | 补全、`/usage` 面板 |
| 选择器（`zone/resume`） | 列表、搜索、附着 / 删除意图 |
| 树（`zone/tree`） | 树形、跳转意图 |
| APP（`app.rs`） | 显示大区那张表、键鼠下发、宽高下发 |
| 契约（`zone/mod.rs`） | Zone / SubZone / 所有权 / 尺寸 / 事件声明 |

各区只声明**意图**（提交、打断、回退、要块、切会话、退出），由一个队列交给 `session`；只从 `session` 拿**只读数据**。

## 五、分组搬到前端

新面给的是**逐行的块**（五档），服务端不再分组。一条工具往返 = 一张卡（按 `call_id` 把请求与结果配起来）由**历史区**在渲染路径上算 —— 它本来就决定「一块长什么样」。成品缓存的键因此是卡片首块的块号。

## 六、渲染的特殊类型：昙花（系统消息）

比参与上下文的块短命的一类东西 —— **昙花**。它不进库、不进上下文、不算卡片，只在屏幕上出现一会儿，两种寿命：

| 类 | 什么时候来 | 什么时候走 |
|---|---|---|
| 短命 | 无伤大雅的那些：超时、正在重试、正在重连 | 下一条**常驻**的东西（一条常驻昙花，或任何一个块）插入时，原地消失 |
| 常驻 | 严重的那些：429、余额不足 | 离开这条对话才走；**退出会话后不复现** |

两条都不落库。今天的「旁白」（协议错误、未知命令、「还没接线」）按这条走：各自认领自己的寿命。

## 九、还没定的

1. **tui 是否接回构建**：`lib.rs` 加回 `pub mod tui;`、`Cargo.toml` 加回 `ratatui` / `crossterm`（今天两处都没有）。

3. **渲染画法是否跟着现代化**：`docs/omp-rendering-survey.md`、`omp-symbols-ascii.md`、`omp-theme-port.md` 那三份参考（markdown 升级、工具卡标题行、思考脉冲、用量行、用户气泡 markdown 化）。
4. **历史区改动多大**：数据来源换掉之后，锚点 / 滚动 / 成品缓存那套要不要顺手动（今天是围绕「服务端分组」写的）。

6. **本地命令的落地接口**：`/q`、`/resume` 这类不跟服务端通信的命令，在大区彼此隔离的前提下，前端要有一个通信的地方。

## 十、配置与状态行组件（2026-10-11 定）

### 配置统一问服务器

- 前端要的任何配置值都问服务器，不由前端自己去读配置文件 —— 要一个 `call config`，收一个键名（`config.ui.lang`、`model.contextWindow`），返回对应的值；键名要写对。
- 服务端今天没有这个口子（`Call` 九条里没有；启动时唯一的元数据口是 `Call::Pools`）。

### git 段自己跑

- 段的数据来自一次 git 快照；**组件自己开一个后台线程**跑，主循环零参与、不拖累帧。
- 节奏：工具结束事件记一笔「有新东西」；距上次干活不足间隔就不干；够了才跑一次；跑完清标记，没新标记就继续歇着。件数不记 —— 一干活就把之前攒的全部视为已处理。
- 间隔默认 3 秒（热缓存下一次快照约 6 ms，本机实测），键名 `config.ui.tui.zone.main.input.deco.gitScanInterval`，允许用户自己写。
- 目录由输入区通知：初始化那一下给一次，之后每次用户 `/cdp` 再给一次；模型自己临时切出去（`[T]`）不管。

### 状态行的件怎么加、怎么撤（2026-10-12 定）

- 只在代码里动：加一件、撤一件都是改注册表、重新编译，**不开用户侧开关**（不加「显示哪几件」「什么顺序」这类配置键）。
- 想让用户自己加件，就让用户自己放代码，不走配置文件。

### activity 的字形与本会话的桥接（2026-10-12 定）

- 静止时画 `π`；**本会话开了某个桥接**（今天说的是 telegram）就画 `Tel`，思考中照旧转圈。判断来自一枚会话状态，由服务端一个 post 告知、前端读视图。
- 只改这一件的渲染，座位、优先级、别的件都不动。

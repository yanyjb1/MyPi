## 写锁：会话级那一半（2026-10-10 定）


库级那一半在 `ipc::server::claim`：一个库一个 server，标准库的文件锁（`File::try_lock`），进程死
内核放锁，第二个进程直接当客户端连上去。要定的是**会话级**那一半：

那条会话的写锁从**用户消息递进来**那一刻起，到**这个回合结束**为止（打断也算结束）。活跃期间不许
往这条会话里**写块**、也不许**破坏性地动它**：

- 挡下：回退（会切掉正在跑的这一回合的块）、删会话（回合还在往一条已经没了的会话里写）。
- 放行：**元数据**（`/name`、`/cdp` 改的那两栏、以及 `/switch` 落的会话行）。用户的话：元数据只是
  方便管理、对人友好，对话本身不需要知道它叫什么、用的是哪个模型 —— 它不碰块的写入。
- `/model` 改的是**配置文件**，不碰库，跟这把锁无关。
- 模型与档案**什么时候**可以切，另开一个开关管（见下）。
- 写者身份 = 持有那条会话的写锁。今天用「这条会话有没有回合在跑」实现，正是这个粒度。
- 两条不同会话可以同时跑：锁按会话算，不按库算。
- 读者不限；谁在看是另一回事（前端显式「关注 / 不关注」，api 那边一张表）。
- 以后两个前端开同一条会话：一个提交，另一个跟着同一条流看（设计已支持，一人一条流）。
- 例外：`/switch` 仍可在回合跑着的时候落 —— 它改的是会话行与**跑着那条连接的目标**，是有意留的。
- 「没人看、没人在跑就收掉那条会话的状态」是 api 的事。

今天的状态：`post` 那扇门还没有这道闸 —— 回退与删会话在回合跑着的时候照样能插进来（第 37 条）。

## 工作目录以 init 为准（2026-10-20 定）

UI 启动时，把前端自己的工作目录随 init 的 post 交上去；后端以这份目录为准，不再自己猜。

- 每条会话持有自己的工作目录。不同会话的目录可以不同；工具并发跑时各用各的，不许共用一个进程级目录。
- 模型自己的 `cd` 只改当前会话的目录，别的会话不受影响。
- `/cdp` 改当前会话的目录；回合跑着的时候，问目录要拿这条会话当下那一份，不许另建一份状态读旧值。
- 工具的临时目录、相对路径解析、bash 的工作目录，全部取自这条会话自己的那份，不许读进程的当前目录。
- 待办第 37 条里「承认旧语义还是等回合结束」的岔路作废，按本条执行；第 45 条的定向初始化与多目录按这条走。

今天的状态：init 的 post 已经带目录，会话行也落了目录，工具环境按会话行建；还没落地的是回合跑着时问目录那一条。

## 模型与档案什么时候能切（Scrooge，2026-10-10 定）


设置里一个开关，名字叫 **Scrooge**。

- **开着**（收紧）：换模型 / 换档案只能落在两个时刻 —— 会话之初、压缩之后的首条消息。
- **关着**（默认，随便换）：任何时候都能换。这条**不靠每次换完都报**，而是在**界面开一条新会话那
  一刻**插一条一次性系统通知，把这句后果说清楚：这一路你随时能换模型 / 换档案，但每换一次，这条
  会话的历史都要重新付一次账单。
- 那条通知**不落库、不进上下文**，就是给人看的一句话（旁白），排在那条界面最新一条消息的位置。
- 话是**占位符**，归 UI：名字按用途起，暂定 `config.tui.placeholder.switchBill`；
  **允许为空**（空 = 不显示）。默认那一句要写得**恭维**一点 —— 就当用户真的是个很有钱的人：
  富哥得到情绪价值，穷鬼得到提醒，熟练的人自己把它改掉或者清空。
- 只在**开关关着**（富哥）的时候显示；开着（收紧）时没有可提醒的事。
- 谁渲染：前端自己（这是纯前端的事，一个「渲染一次」的状态）。**但**远程前端读不到本机的配置
  文件，所以那枚开关与那句话大概要由服务端在**初始化**时交给它（还没有这个读口，见待办第 38 条）。
- 是不是跨会话（切回旧会话还显不显）**待定**，倾向只在新会话那一次显示。
- 今天代码里的样子：`/switch` 改会话行、并让跑着的那条连接换目标（下一个回合生效）；`/profile` 要等
  下一个「两个时刻」才真正生效。

（2026-10-10 定）

## 会话从哪儿算起


一个会话的开始是两个时刻：

1. 用户的第一条消息
2. 压缩之后的第一条消息

**只有消息建会话，命令不建。** 首条消息之前，用户可能先敲 `/switch`、`/name`、`/profile`
这类命令：那些状态由**前端自己拿着**，随首条消息一起交上来，后端收到才开始初始化、才写入。
一条命令就开一个会话，resume 时会出现一堆幽灵会话。

`/profile` 只能在这两个地方切换配置，别处不许出现。

工具名单（给模型发哪些工具定义）也在这两个时刻定一次，之后不再变。

（第 24 条）。另有一枚 `reloadOnCompaction` 开关，管的是"压缩之后要不要重读档案"，缺省关，语义还没实现。

## 多语言与热重载（2026-10-10 定）


### 语言是全局的

一枚值，一个进程一份。**不做「每个前端一种语言」** —— 前端不该能改这件事。选语言是一条命令，
按 `/model` 的现成模式落配置文件。

### 配置能热重载

谁需要新值谁自己再拿一次（比如前端重拿那两份名单、界面重拿占位符文本）。

- 占位符那套不变：库里存**名字**、渲染时问配置 —— 所以换语言只影响渲染那一头。

## TUI 侧：分而治之、大胆放权（2026-10-11 定）


前后端的原则相反。后端要一个明晰的状态：库的读、库的写、切块都集中在一处。前端杂，所以**大胆放权** —— 谁的事谁管，谁最终消费谁解释。

- 界面的每一块自己管自己的交互与状态：键位捕捉与语义、滚动、折叠、锚点、成品缓存（渲染好的卡片）、补全、选择器、树，全归各自的区。
- 会话侧只管三件：和后端打交道、会话状态、原料缓存（待渲染的块）。
- 组件不碰后端：api 的调用全部收在会话侧，会话给一个**统一入口**，组件只走那个入口。
- `call` 与 `post` 分开对待：`post` **不带答复**（错了才是例外；只有建会话那一条回 id），所以 `post` 改的东西**先乐观落地、提前渲染**（照 `/name` 那个样子）；`call` 是问，等答复。
- 用户行为与其他行为分两类：
  - **action**：用户干的（按键、粘贴、鼠标、提交、打断、回退）。由最终消费它的那个区解释，语义归区。
  - **事件**：不是用户干的（后端的推送、git 快照、resize、重绘、空拍）。由需要它的那一侧接收。

（2026-10-11 定）

## TUI 侧：事件与键鼠（2026-10-11 定）


事件只有两条来源，归一化到一条枚举，APP 收到后**广播**，只给显示区。键鼠是用户行为，按**谁消费归谁**定点下发。

### 事件的两条来源

- **运行时事件**（我们自定义的）：回合开始、回合结束、内容（块到来、工具调用、旁白）、时间（空拍、期限到）、连接（断线、重连）。
- **用户行为不产生事件**：它走 `Action` 那条线（按消费权定点），后果要么在区内部（命令归输入区），要么走 `Request` / `Handover`；状态变了靠每帧读视图，不靠事件。
- **系统环境事件**（我们定义不了的）：尺寸变化、挂起与恢复、焦点得失、终端没了（SIGHUP / SIGTERM）、输出断了（EPIPE）。
- 空拍 = 屏幕上还有东西在动但没有新东西进来，循环自己给自己发一个信号。期限到 = 先前说好「到某个时刻要发生一件事」，现在到了（Esc 双击窗口、重连退避、重试间隔）。
- 回退、压缩、打断是**用户行为**（action），不是事件；它们的后果（回合结束、块到来、占位落地）才是事件。

### 下发

- 事件归一化后广播，**只给持显示权的那一个大区**。
- 键鼠按消费权**定点**：谁消费归谁。
- 尺寸并进事件，不再走 `attach` / `on_resize` 两条独立的口。

### 键身份

- 归一化到「一个值能说出 Ctrl+D」的粒度：字符或具名键 + 修饰键（Ctrl / Alt / Shift）。
- 不带 crossterm 的 `kind`（Press / Repeat / Release）与 `state`（CapsLock / NumLock / Keypad）—— 那两个字段会让同一个物理键互不相等，表里写好的那一行查不到。
- 落不到这个粒度的（没有键盘增强协议时 Ctrl+Shift+字母）归「其他」，没人认领。
- 归一化只做投影，不做解释：Ctrl+D 不翻译成「退出」或「删字符」。

### 注册表（两级三张）

- APP 级：大区注册表（在册的大区）+ 显示权账本（现在是谁）。
- 主区级：子区注册表 + 键位表（键 → 子区）。
- 键位表三档行：具体键（Ctrl+D → 输入区）、类别（粘贴 → 输入区、滚轮 → 历史区、任意字符 → 输入区）、兜底（其余丢掉）。类别那一档必须有，否则输入区要吃全部可打印字符就得列 95 行。
- 建法：**形状取「子区自己交表」**（谁消费谁登记），**检查取编译期 match**（同一个键登记两次 = 不可达分支，编译期报），运行期零表；借键那一小份走运行期同一张表。

### 通知（hook）

- 回合结束且焦点不在（用户不在终端前）→ 发一条通知。
- 发通知那一步按平台来，平台由服务端给；一个事件可以挂一条自定义命令。

### 命令归输入区

- 斜杠命令这一类（`/name`、`/model`、`/cdp`、`/usage`、`/switch`、`/compact`、回退…）由输入区捕捉、解释、落地。
- 它的消费者基本就在输入区自己或与它联动的保留区里（状态行在输入区里，面板在保留区），所以一家解决，别的区不用知道。
- **命令不是事件**，是输入区的内部事务。主循环只捕捉键，连命令存在都不知道；键到输入区手里才攒成命令。
- 出地界只有两个门：要落到会话的走 `Request`（提交、打断、回退、切会话），要交显示权的走 `Handover`。没有第三个门。

### 行高（聊天大区的内部约定，未来重构三个子区时）

- 仲裁留在主区（APP 把高度报给主区）—— 「聊天大区与其子区」的内部约定，不挂到通用契约上。
- 变动只有两个来源：输入区的内容变了、保留区被激活。
- 挂起走一个握手：触发方要回执，输入区拿到回执才正式挂起 —— 于是输入区是唯一知道动态行高的人（它知道自己多高，也知道保留区要占多高）。
- 输入区变了 → 通知主区（中间商，手里有最准的全局高度）→ 主区算历史区剩余预算 → 通知历史区。

（2026-10-11 定）

## 初始化（2026-10-11 定）

- 负责初始化的是**主区（聊天区）**：第一条用户消息 `submit` 出去之前，它把攒下的状态通过 `Post::Init` 交上去。

- 工具那一侧跟着两件事：按前端传回的路径做**定向初始化**（主要是 bash —— 只有它特别强调路径）；**支持多目录**。

## 配置值按键名取（2026-10-12 定）

## 原料缓存比成品缓存激进（2026-10-13 定，2026-10-14 补齐）

session 的原料（块）缓存管理，必须比成品（渲染好的块）缓存管理更激进。整条设计连同上游那一半，落在 `src/ui/tui/zone/main/history/HISTORY-DESIGN-MEMO.md`。

- 滑动的方向就是索引的方向：历史区往上滑，原料立刻往上索引；往下滑，立刻往下索引。
- 取数按回合，不按块数。一次要多少由 `config.ui.session.askedEachTime` 定，默认 32。
- 只考虑两种情形：全新的对话；恢复到一条历史会话。
- 历史区一个口两种报法：跳跃中只报回合号；跳完了报具体要哪几块。连着跳的时候回来的量减到 8（第 3 次起指数递减，底 4），这个减量状态由 session 自己维持。
- 历史区静默 `config.ui.tui.zone.main.history.restYourMouse`（默认 300 毫秒）之后发一条回执；回执只抹掉减量状态，不等答复、也不触发补问，补齐由历史区按常态自己再要。
- 不检查空行、不补空白：能空白就让它空白，这一块的用户体验是故意牺牲的。

两个缓存分工：

- 内容缓存装块号到内容，固定 128 块。管的是占用，不让一条长对话把内存顶上去。
- 结构缓存装回合怎么管块，是个索引，不装内容；恢复会话时一次给全，之后只走增量。

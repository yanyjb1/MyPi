# 说明

WebUI是Bridge的满血实现，之后所有的接入者具体声明什么参考webui即可。

# 要求

原生JS，不允许引入任何其他框架，单个html/js/css文件不允许超过800行。

适配手机端和桌面端，利用现代浏览器提供的各种api来确保兼容。

# 布局

左侧：会话管理面板，包括：按钮（开启新会话）列表（所有历史会话，每个历史会话有一个rename和delete的按钮，具体显示什么需要国际化）以及最下侧的设置面板入口（暂时留空，占位符，使用一个齿轮的模样，但是是用svg画的）。

中间：历史会话区&输入框。输入框有修饰，修饰位于输入框下方，在输入框内部，从左到右依次包含：工作目录（平时不可编辑，双击之后变得可以编辑，而后由用户手动输入路径，此时需要路径补全配合），git分支与工作区状态（具体设计参考ohmypi），该会话历史花费（参考tui的实现，货币符号+具体数字），effort&模型（均通过下拉列表选取）。不支持effort的模型直接不显示effort。

右侧：临时注册面板，不设置固定形态，由拉起者自己决定往里边写什么内容、写什么内容。被写入的内容不自动更新，除非下一个人写入新内容。写入可以是更新局部数值也可以是整个重写，由拉起者自己决定。

刻度盘：在历史区右侧，拉出面板时隐蔽，分为激活和未激活两种状态，未激活时以轮盘刻度显示本会话内总共几条用户消息，30°一条，有消息上限，实际上实现的就是树区的功能。
激活时，刻度盘的30度一条（或者换成60°一条也行，总之固定间隔），显示用户消息，也就是轮的回合，激活刻度盘时，鼠标滚轮从滚动上下文变成滚动轮盘，也就是滚动用户消息，一次滚动一条。

有一条用户消息，就在这个轮盘上刻一个刻度。在用户消息不足半个轮盘的刻度时，只氪那么几条，不要为了这个东西给我氪一天吗？
刻度盘实际上是一个半圆环，激活的时候只是把它扩大了一些。

点击圆环的刻度，也就是，激活状态下点击具体的用户消息时，将跳转到对应的历史。

webui的块渲染遵循如下规律：
工具的渲染，将模型的intent参数作为显示出来的内容，大致形体：
{工具名}：{intent}，intent右侧一个小按钮，可以展开工具调用的细节，也就是展开参数、结果等细节，每个工具单独展开，特殊键位全局展开。
一般工具的渲染样式，分为首部和尾部，首部用来放模型的工具调用请求，尾部用来放工具调用结果，先设立兜底的，之后再具体细化每一种工具的渲染。

模型思考，做成可折叠的，折叠时只显示一个thinking

用户消息和模型正文，不做折叠。

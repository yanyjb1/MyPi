# 设计说明

## 模块定位

fs/lang 是支撑四件套（read / grep / splice / write）的语言感知与中立调度基座。它不构建通用 AST，而是作为轻量语义透镜，为模型提供行级结构坐标、局部邻里拓扑与统一体检裁判。

## 场景预设

1. 混血与暂态破损：现实仓库天然由多语言交织，且模型编辑过程中代码常处于局部语法残缺状态。解析底座必须容忍脏状态，绝不能因单点错误导致系统崩溃。
2. AST 不通用，生态自成体系：各语言组织哲学差异极大，不存在放之四海皆准的语法树。生态自带的官方工具链（编译器/格式化器）即最权威法官，无需在引擎内自建解析体系。
3. 拓扑求近不求全：模型不需要吞下全仓库调用网络（避免打翻 Token 上下文），只需感知当前工作区的十字路口（向下管辖、向上调用、对外依赖）。

## 核心设计

### 结构大纲（Table）：行号稳定与结构切片

1. 剥离具体语法细节，仅提取代码块起始与闭合的物理行号。
2. 为 read 提供折叠视图，为 splice 提供不可漂移的精确定位基准，杜绝改一行导致全篇行号失效。

### 邻里拓扑（Graph）：事实解耦与受控向上回溯

1. 事实与状态分离：具体语言仅提供轻量文本事实（纯文本声明与引用）；图引擎负责跨文件归一化、折叠自引用并组装邻里。
2. 预算熔断与整层丢弃：向上反查调用者时实行分层推进与时间熔断（首层必跑完，后续共用 300ms）。超时则丢弃整层而非返回残血数据，防止模型将未搜完误判为无引用。
3. 显示预算控制：高密度调用按目录自动折叠，行长超限自动截断，严格压制上下文膨胀。

### 门禁与裁判（Verdict）：只验不改与非侵入式体检

1. 语法门禁（format）：仅在语法解析彻底崩溃（如括号失配破坏文件骨架）时阻断写入，其余情况零干涉。
2. 体检与单测（check / test）：落盘后静默触发原生工具链，将诊断清洗为中立回执反馈给模型，不阻断流程，交由模型自主修复。
3. 法官缺席不开庭：本地缺少对应语言工具链时静默降级放行，绝不阻断正常编辑。

### 插件式插槽（Registry）：绝对隔离与优雅降级

1. 正交填槽：语言契约划分为独立能力槽位（大纲、门禁、体检、单测、图谱、符号关系），能支持的填槽，不支持的置空自动降级。
2. 横向绝对隔离：各语言目录完全自治，严禁横向依赖与跨语言伪抽取，新增语言单文件接入，公共层零感知。
